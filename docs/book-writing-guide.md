# 书稿编写规范(全系列通用)

> 本规范从 agentscope-java 书的成稿形态归纳,是书架内**所有书籍**章节编写的统一标准。
> 新章节动笔前通读一遍;评审按此逐项对照。
> 现状对照:mcp 书初稿 v2 为"规范对照 + 实测记录"形态,**尚未按本规范扩充为书稿**,后续按本规范增厚。

## 1. 文件与元数据

- 章节路径:`books/<book-id>/chapters/NN-slug.md`(NN 两位章号,slug 小写连字符)
- frontmatter 三字段:

```yaml
---
chapter: 4
title: Agent 与 ReAct 循环
source: docs/building-blocks/agent.md   # 来源;依据官方文档的书写官方路径,原创章写「原创」并附依据材料
---
```

## 2. 章节骨架(固定顺序,不得缺省)

```markdown
# 第 N 章 章标题

> 本章导读:……

[章首 mermaid 图:操作流程图(操作章,默认)或导览图(概念/总览章)]

*本章操作流程图* 或 *本章导览图*

## 你什么时候需要它

## 概述

## (主体 H2 节 × N,每节内 H3 子节展开)

## 本章小结

## 验收清单

## 参考速查(可选)

## 延伸阅读
```

各节职责:

| 节 | 职责 | 写法要点 |
|----|------|---------|
| **本章导读**(blockquote) | 开场即回到贯穿案例,点出本章解决的核心问题/要做的决定,预告内容清单,收在「读完本章,你能……」 | 一段 150-250 字;不说废话,直接建立"为什么有这一章" |
| **章首图** | 按章性质二选一(细则见 §4 图表):操作章用**操作流程图**,图注 `*本章操作流程图*`;概念/总览章用**导览图**,图注 `*本章导览图*` | 节点文字具体(不写"介绍 XX",写"选类与调用方式:ReActAgent 还是 HarnessAgent") |
| **你什么时候需要它** | 场景决策:三种典型处境 → 各自的选择;并与已学章节建立连接 | 实用主义入口,读者可只读这节就做对决定 |
| **概述** | 概念铺垫;核心接口/概念用表格呈现 | 「业务上推荐优先用 X」这类立场句加粗 |
| **主体 H2 节** | 按"决定/任务"组织,不按 API 字母序;每节 = 问题 → 方案 → 可运行代码 → 边界与坑 | H3 子节展开;关键概念必有代码;对比内容表格化 |
| **本章小结** | 编号要点回顾(对应开头的问题)+ 下一步建议(跨章衔接) | 衔接写具体:「第 6 章讲 `.model(...)` 背后的模型接入」 |
| **验收清单** | ☐ 复选框 5-7 条,**可自测的动作句**(「说出 X 与 Y 的分工并选定」「完成一次带确认的调用:接收 A、回传 B」) | 不是知识罗列,是可验证的行为 |
| **参考速查**(可选) | 参数表/配置表等查阅性内容 | 开头注明「理解主线不依赖本节」 |
| **延伸阅读** | 相关章节/相关书的引用,每条附一句"为什么相关" | 3-5 条 |

## 3. 厚度标准

- **每章正文 ≥ 500 行**(Markdown 行数);典型 600-900 行,平台/专题章可到 1000+
- 低于 400 行的章节不是书稿,是大纲——退回扩充
- 代码示例密度:每个关键概念一段可运行代码;示例之间共享同一套对象/系统,渐进演化而不是每次另起炉灶
- 表格优先:接口清单、方案对比、参数说明一律表格化

## 4. 图表

- 章首图必备(内容极简的章可免,需在评审说明),按章性质二选一:
  - **操作流程图**(默认,操作步骤类章节):mermaid `flowchart LR`,按读者动手的真实顺序画主线——起点即动作,终点为可验证状态;决策分支画进图里(菱形节点,如「按更新频率选接入路线」),每个节点标注对应小节号,跨节动作标双小节号(如 `3.2 · 3.5`);概念性小节(如概述)不占节点。参考实现:ragflow 书第 3 章
  - **导览图**(概念/总览章):mermaid `flowchart LR`:需求 → 本章主题 → 分支要点 → 收益
- 文内按需 mermaid 时序图/流程图/部署图,有名就用(数据流、生命周期、拓扑)
- **文字过多时,优先改画成 mermaid 图提升可读性**:并列要点 ≥4 条(改 flowchart 分支)、步骤 ≥5 步(改 flowchart 或 sequenceDiagram)、状态/模式 ≥3 个(改 stateDiagram-v2)、概念间有层次或包含关系(改 classDiagram/graph)——大段"第一…第二…第三…"的枚举文字是图表化的首选对象
- 章首图一律横向布局(`flowchart LR`),节点文字 2-3 行、每行要短,全图控制在 6-8 个节点——图过宽或过高都会被页面缩放到文字不可读
- 必须在 GitHub 网页端原生渲染(mermaid 标准语法,不依赖插件)

## 5. 语言与标点

- **书稿正文使用中文全角标点**(,。;:「」""——);与仓库元数据(registry、README 表格)的半角风格区分
- 代码、命令、标识符、文件名、HTTP 头保持原样半角
- 跨章引用格式:「(见第 N 章)」「(→ xxx 书)」
- 术语首次出现给中英对照:人工介入(Human-in-the-Loop)

## 6. 贯穿案例

- 每本书一个贯穿案例(agentscope-java 书为「星帆出海客服 Agent 小帆」;mcp 书为「中台售后域:20 接口 → 6 工具 → Gateway → 多框架」)
- 章首导读回到它;主体示例共享它;小结回收它;案例随章节推进而成长
- 贯穿案例的数据(单号、域名、接口名)全书一致,禁止各章自造

## 7. 质量门槛

- 代码示例实测通过,或显式标注「未实测」并附实测清单(放在章末复核清单)
- 外部事实(版本号、行为、数据)标注出处与核实日期
- 交叉引用发布前全量检查不断链
- 事实层与立场层分离:规范/文档说的标注出处;本书观点明确为立场

## 8. 与书架元数据的关系

- registry(`build/books/registry.mjs`)是书名/一句话简介的单一来源,与书稿正文的半角元数据风格一致
- 书级 README 的章节表链接到 chapters/ 实际文件
- 站点构建(book 升 published)前,按 build/README.md 跑全链路预演
